## Answer

**Yes — the default handling of unknown keys did change.** Your memory matches a real (if brief) window in Zod's history: during Zod 2's development, `z.object()` defaulted to **keeping** unknown keys, and then commit `1885449` flipped the default to **stripping** them. That strip default has been in force ever since, including in this checkout.

**The commit that establishes the answer: `1885449` — "strip unknown keys by default" (Colin McDonnell, 2020-09-17).**

The code diff (`src/types/object.ts`) changes the object factories' default from keep to strip:

**The fuller timeline** (all in this repo's history):

- **Zod 1:** `z.object()` default was *strict* — unknown keys caused an error (`params: { strict: true }`), so it never silently kept them.
- **`2936e65b` "Eliminated params from ZodObject" (2020-09-15, during Zod 2 dev):** the default became `unknownKeys: 'allow'` — objects **kept** properties you didn't define. This is the behavior you remember; it also shipped in the v2 beta (`3a7a6ea0` "published v2 beta" precedes the strip change).
- **`1885449` "strip unknown keys by default" (2020-09-17):** the default flipped to `unknownKeys: 'strip'` — extra keys disappear from the output. (Same commit renamed the mode `'allow'`→`'passthrough'` and the methods `.stripUnknown()`→`.strip()`, `.allowUnknown()`→`.passthrough()`.)
- **Now (this pinned HEAD):** `ZodObject.create` still hardcodes `unknownKeys: "strip"` (e.g. `packages/zod/src/v3/types.ts`), so parsing `{ name: "bob dylan", extraKey: 61 }` with a plain `z.object({ name: z.string() })` yields only `{ name: "bob dylan" }`.

So the "keeping" default never made it into a stable Zod 2+ release — it lived only in the v2 development/beta window between `2936e65b` (Sept 15) and `1885449` (Sept 17, 2020). If you want the old behavior today, the escape hatch is `.passthrough()` (or `.nonstrict()`), which re-enables passing unknown keys through.
