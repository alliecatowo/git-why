## Answer

The requests library replaced **chardet** with **charset_normalizer** as the default text-encoding guesser primarily for **licensing reasons**: chardet is LGPL-licensed, while charset_normalizer is MIT-licensed.

### Supporting commit

**SHA:** `2ed84f55b22f19a1e1e8eea2e50963dce62052d3`
**Subject:** `Switch LGPL'd chardet for MIT licensed charset_normalizer (#5797)`
**Author:** Ash Berlin-Taylor · **Date:** 2021-07-06

### Commit message (quoted)

> Switch LGPL'd chardet for MIT licensed charset_normalizer (#5797)
>
> Although using the (non-vendored) chardet library is fine for requests
> itself, but using a LGPL dependency the story is a lot less clear
> for downstream projects, particularly ones that might like to bundle
> requests (and thus chardet) in to a single binary -- think something
> similar to what docker-compose is doing. By including an LGPL'd module
> it is no longer clear if the resulting artefact must also be LGPL'd.
>
> By changing out this dependency for one under MIT we remove all
> license ambiguity.
>
> As an "escape hatch" I have made the code so that it will use chardet
> first if it is installed, but we no longer depend upon it directly,
> although there is a new extra added, `requests[lgpl]`. This should
> minimize the impact to users, and give them an escape hatch if
> charset_normalizer turns out to be not as good.

### Supporting diff excerpt

The commit updated `docs/user/advanced.rst` to describe the new behavior:

```
+If ``chardet`` is installed, ``requests`` uses it, however for python3
+``chardet`` is no longer a mandatory dependency. The ``chardet``
+library is an LGPL-licenced dependency and some users of requests
+cannot depend on mandatory LGPL-licensed dependencies.
+
+When you install ``request`` without specifying ``[use_chardet_on_py3]]`` extra,
+and ``chardet`` is not already installed, ``requests`` uses ``charset-normalizer``
+(MIT-licensed) to guess the encoding.
```

It also added the optional extra in `setup.py`/`setup.cfg` (`use_chardet_on_py3 = ["chardet>=3.0.2,<8"]`) and updated `requests/compat.py`, `requests/help.py`, `requests/models.py`, and `requests/packages.py` to prefer chardet when present but otherwise fall back to charset_normalizer.

### Note

The changeover was a *default* swap, not a hard removal: chardet still wins if it happens to be installed. The current checkout reflects this — `src/requests/compat.py` resolves `("chardet", "charset_normalizer")` in that order, and `pyproject.toml` lists `charset_normalizer>=2,<4` as the dependency with `chardet>=3.0.2,<8` available as the `use_chardet_on_py3` extra.

No files were modified.
