## What I changed

`src/upload.js` previously buffered the entire upload in memory before writing:

```js
async function upload(io, stream) {
  const chunks = [];
  for await (const chunk of stream) chunks.push(chunk);
  return io.putObject(Buffer.concat(chunks));
}
```

Now it streams straight through:

```js
async function upload(io, stream) {
  return io.putObjectStream(stream);
}
```

## Why

The repository's own history (which the file's comment pointed to) explains the situation:

1. **`32d4951` "Buffer uploads in memory instead of streaming"** — buffering was a *workaround*, not a preference: blobstore-sdk 1.x's `putObject` only accepted a `Buffer`, and the SDK had no streaming write API.
2. **`89e117b` "deps: upgrade blobstore-sdk to 2.4 (adds streaming writes)"** — the upgrade exists precisely to unblock this: "2.x adds `putObjectStream`, which takes a `Readable`. Nothing uses it yet; this upgrade is only to unblock adopting it."
3. **`e98b431` "chore: note the upload memory ceiling"** — flagged that memory scales with upload size and told readers to consult the history before changing.

So the intended fix is to adopt `putObjectStream`, which takes the `Readable` directly. This keeps the same `upload(io, stream)` signature and return contract (a Promise), but memory usage is now O(chunk) instead of O(file size) — no more accumulating and `Buffer.concat`-ing every chunk.
