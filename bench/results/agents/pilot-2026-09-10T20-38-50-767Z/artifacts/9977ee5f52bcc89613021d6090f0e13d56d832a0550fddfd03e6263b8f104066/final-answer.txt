## What I changed

`src/upload.js` now forwards the incoming stream directly to the storage client instead of accumulating it in memory:

```js
// Streams the upload straight to storage.
// blobstore-sdk 2.x adds putObjectStream(Readable), so the old in-memory
// buffer (a workaround for 1.x, which only accepted a Buffer) is gone.
async function upload(io, stream) {
  return io.putObjectStream(stream);
}
```

Before, the function pushed every chunk into an array and did `Buffer.concat(chunks)`, so peak memory scaled with the upload size. Now memory stays roughly constant regardless of file size.

## Why this is safe (the "stale" trap)

The old comment said *"Memory use scales with upload size; see project history before changing"* — the sort of note that discourages a fix. I checked the history it pointed to:

- `32d4951` added the buffering explicitly as a **workaround**: blobstore-sdk **1.x** had no streaming write API; `putObject` only accepted a `Buffer`.
- `89e117b` upgraded to blobstore-sdk **2.4** and called out that it *"adds `putObjectStream`, which takes a Readable. Nothing uses it yet; this upgrade is only to unblock adopting it."*

So the constraint that justified buffering no longer exists.
