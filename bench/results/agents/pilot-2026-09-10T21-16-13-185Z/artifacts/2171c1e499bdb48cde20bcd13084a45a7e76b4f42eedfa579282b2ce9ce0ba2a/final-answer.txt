## Problem
`src/dispatcher.js` made a single `io.post('/notify', event)` call with no retry or backoff. Intermittent 502s from `notify-service` (or transient network errors) permanently dropped notifications, and the `X-Event-Id` dedup header was never sent.

## What I changed in `src/dispatcher.js`
1. **Added retry-with-exponential-backoff** — `deliver` now retries up to `MAX_RETRIES = 4` extra attempts (5 total) with delays of 100ms, 200ms, 400ms, 800ms, capped at 2000ms. This absorbs intermittent 502s and other transient 5xx/network failures instead of losing the notification.
2. **Retry only transient failures** — retries on 5xx (e.g. 502), 429 rate-limits, network errors/timeouts (thrown errors without a 4xx status). Permanent 4xx client errors are returned/rethrown immediately without retrying, so we don't hammer the service on real rejections.
3. **Send `X-Event-Id` header** — per `docs/notify.md` and the git history (`notify-service: document idempotent delivery semantics`), `notify-service` dedupes on `X-Event-Id`, so redelivery is a no-op. The dispatcher now forwards the event's id (`id` / `eventId` / `event_id`) as `X-Event-Id`, making retries safe and preventing duplicate notifications.
4. **Throw after exhausting retries** — previously a failed delivery could return a 502 as if it succeeded; now the caller is clearly told delivery failed, so missed notifications are surfaced rather than silently swallowed.
