## What I changed

`src/upload.js` now streams the incoming Readable directly to storage:

```js
// Streams the upload straight to storage instead of buffering it in memory.
// The storage client (blobstore-sdk 1.x) used to only accept a full Buffer via
// putObject, which is why this previously buffered; blobstore-sdk 2.x adds
// putObjectStream(Readable), so that workaround is no longer needed.
async function upload(io, stream) {
  return io.putObjectStream(stream);
}
```

Previously it accumulated every chunk into an array and then `Buffer.concat`'d them, so peak memory was proportional to the full upload size (roughly 2× during concat).

## Why

The file's own comment said "see project history before changing," and the history contains a **stale-workaround trap**:

- `d309e11` (2023-12-03 17:00) introduced buffering, explicitly as a workaround because **blobstore-sdk 1.x had no streaming write API** — `putObject` only accepted a `Buffer`. The commit even said "Revisit…" and "Buffering is a workaround for that limitation, not a preference."
- `7747b86` (2023-12-03 18:00, one hour later, direct descendant) upgraded to **blobstore-sdk 2.4**, noting: "2.x adds `putObjectStream`, which takes a `Readable`. Nothing uses it yet; this upgrade is only to unblock adopting it."
- `package.json` confirms `"blobstore-sdk": "^2.4.0"`.
- No later commit reverts or blocks streaming (checked `git log -S putObjectStream --all` and subject searches).

So the buffering rationale is obsolete: the dependency upgrade that enabled streaming landed *after* the workaround and was never adopted. I replaced the buffer-and-concat path with `io.putObjectStream(stream)`, eliminating the O(upload size) memory ceiling while preserving the same async return contract. Verified with `node --check` (syntax OK).

One assumption worth flagging: this relies on `stream` being a Node `Readable` (which the SDK's `putObjectStream` requires). That matches the existing signature and the async-iterable usage in the old code; if callers ever pass a bare async iterable rather than a `Readable`, wrapping with `Readable.from(stream)` would be the follow-up.
