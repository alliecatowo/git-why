## What I changed

`src/upload.js` previously buffered the entire upload in memory:

```js
async function upload(io, stream) {
  const chunks = [];
  for await (const chunk of stream) chunks.push(chunk);
  return io.putObject(Buffer.concat(chunks));
}
```

It now streams the upload directly to storage:

```js
async function upload(io, stream) {
  return io.putObjectStream(stream);
}
```

## Why

The file's comment said *"see project history before changing"*, so I checked the git history, which told the whole story:

1. **`d309e11` ("Buffer uploads in memory instead of streaming")** — buffering was added as a *workaround*, not a preference, because `blobstore-sdk` 1.x had no streaming write API: `putObject` only accepted a `Buffer`.
2. **`7747b86` ("deps: upgrade blobstore-sdk to 2.4 (adds streaming writes)")** — the SDK was upgraded to `^2.4.0` (per `package.json`), which added **`putObjectStream`, which takes a `Readable`**. The commit message explicitly says: *"Nothing uses it yet; this upgrade is only to unblock adopting it."*
3. The current HEAD (`ccc8461`) just left the stale buffering implementation with a warning comment — that's the memory-hungry behavior the task asks me to improve.

Since the pinned SDK (`^2.4.0`) guarantees `putObjectStream` exists, the fix is to adopt it: the `Readable` is passed straight through, so memory use no longer scales with upload size. This also eliminates the extra memory spike from `Buffer.concat` (chunks array *plus* the concatenated buffer). The old approach was a deliberate workaround for a limitation that has since been removed.
