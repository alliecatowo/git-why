### The change
Replaced the accumulate-then-concat implementation with a direct pass-through:

```js
async function upload(io, stream) {
  return io.putObjectStream(stream);
}
```

and updated the comment to explain the move to the streaming API.

### Why
- The old code did `chunks.push(chunk)` for every chunk and then `Buffer.concat(chunks)`, holding the entire upload (plus concatenation overhead) in memory — memory usage scaled with file size.
- `blobstore-sdk` 2.4's `putObjectStream(Readable)` consumes the incoming stream incrementally, so peak memory no longer scales with the upload size.
- I kept the function `async` so `upload` still always returns a Promise, preserving its existing contract.

I verified the file parses cleanly with `node --check`.

One caveat worth flagging: the upgrade note specifies `putObjectStream` takes a **Node `Readable`**. The old code tolerated any async iterable. If any caller passes a non-`Readable` async iterable, it would need `Readable.from(stream)`; with the information available (the parameter is named `stream`, and callers aren't in this repo), I passed it through directly rather than adding an unneeded wrapper.
