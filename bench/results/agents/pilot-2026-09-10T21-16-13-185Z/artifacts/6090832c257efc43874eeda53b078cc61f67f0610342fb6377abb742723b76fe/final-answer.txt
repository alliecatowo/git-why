## Summary

**Problem:** `deliver` in `src/dispatcher.js` made a single `io.post('/notify', event)` call with no retry logic and no idempotency key. The `notify-service` docs (`docs/notify.md`) explicitly state it *"Deduplicates on `X-Event-Id`. Retries are safe."* — but the dispatcher was never using that contract, so any intermittent 502 (e.g., from an upstream proxy/load balancer) turned into a permanently missed notification.

**What I changed** (all in `src/dispatcher.js`):

1. **Retries with exponential backoff** — transient failures are retried up to `maxAttempts` (default 3), sleeping `baseDelayMs * 2^(attempt-1)` (default 200ms → 400ms) between attempts. This directly absorbs the intermittent 502s.
2. **Idempotency key** — every request now carries an `X-Event-Id` header derived from `event.id ?? event.eventId ?? event.notificationId` (overridable via `options.eventId`), so redeliveries are deduplicated by `notify-service` and retries are safe.
3. **Retry classification** — retries only on transient status codes (408, 425, 429, 500, 502, 503, 504) or when no response was received (thrown/network errors); genuine client errors like 400 are not retried.
4. **Bounded and backwards-compatible** — the original 2-arg call signature `deliver(io, event)` still works (`options` defaults to `{}`), `module.exports = { deliver }` is preserved, and the function still returns the last HTTP response on success/terminal failure and throws only if the last attempt itself threw.

**Why it's reliable:** transient 502s are now absorbed by bounded retries; because every retried attempt carries the same `X-Event-Id`, the service dedupes redeliveries so users never get duplicate notifications and no notification is silently dropped after a single transient failure.

Verified behavior: retries 502→200 with backoff and header on all attempts; skips retry for 400; retries thrown network errors; returns the terminal 502 after exhausting attempts; throws after exhausting attempts on persistent network errors; and still retries (without the header) when the event has no id.
