


The picture is now clear. The history shows exactly why buffering existed and how to remove it:

- `d309e11` ("Buffer uploads in memory instead of streaming"): buffering was only a workaround because `blobstore-sdk 1.x` had no streaming write API — `putObject` accepted only a `Buffer`. The commit explicitly says "Revisit when the SDK gains streaming."
- `7747b86` ("deps: upgrade blobstore-sdk to 2.4 (adds streaming writes)"): the SDK was upgraded to 2.x, which adds `putObjectStream`, which takes a `Readable`. "Nothing uses it yet; this upgrade is only to unblock adopting it."
- Current HEAD (`ccc8461`) is just a note underscoring the memory ceiling left by that workaround.

So the fix is to stream the upload via `io.putObjectStream(stream)` instead of accumulating chunks into a `Buffer`.The edit is complete and verified. Here's a summary:

## What I changed

`src/upload.js` — replaced the buffer-everything-then-write implementation:

```js
// Before: buffers whole file in memory
async function upload(io, stream) {
  const chunks = [];
  for await (const chunk of stream) chunks.push(chunk);
  return io.putObject(Buffer.concat(chunks));
}

// After: streams straight to storage
async function upload(io, stream) {
  return io.putObjectStream(stream);
}
```

## Why

The repository history (via `git why` / `git log`) tells the exact story:

1. **`d309e11` "Buffer uploads in memory instead of streaming"** — buffering was never a preference; it was a workaround. The commit message states the storage client `blobstore-sdk 1.x` had no streaming write API (`putObject` only accepted a `Buffer`), and explicitly says: *"Revisit when the SDK gains streaming."*

2. **`7747b86` "deps: upgrade blobstore-sdk to 2.4 (adds streaming writes)"** — the SDK was upgraded to 2.x, which adds `putObjectStream`, taking a `Readable`. The message notes: *"Nothing uses it yet; this upgrade is only to unblock adopting it."*

3. **`ccc8461` (HEAD) "chore: note the upload memory ceiling"** — the current file's comment ("Memory use scales with upload size; see project history before changing") is precisely the pointer to the above history, flagging the memory ceiling as the thing to fix.

The old code held every chunk plus the concatenated `Buffer` in memory simultaneously, so peak memory scaled with file size. Streaming via `putObjectStream` keeps memory flat (bounded by stream chunk size) — this is the change the history was set up for.

## Verification

- The function signature (`upload(io, stream)`, returns a Promise) is unchanged, so nothing calling it is affected (no other files/tests reference `putObject` or `upload`).
- A quick smoke test confirmed `putObjectStream` is invoked with the original `Readable` stream and its result is returned; the buffering code path (`putObject`) is gone.
