### What I changed (`src/session.js`)
I added a cache that is **tenant-scoped and not a process-global flat namespace**, keyed on `(tenant context, tenantId, sessionId)`:

- The cache is stored in a module-level `WeakMap` **keyed by the caller's `io` context**, so entries are isolated per context and garbage-collected with it — no shared flat map keyed only by session id.
- Within a context it is additionally **partitioned by `io.tenantId`**, so even if a single context served multiple tenants, an id collision can't cross the tenant boundary.
- It caches the **in-flight promise**, so concurrent misses for the same session coalesce into one `loadSession` (the actual source of latency under load), not just sequential repeats.
- **Rejections are evicted**, so transient failures retry instead of being cached forever.
- I replaced the now-inaccurate `// Uncached by design` comment with the reasoning and the commit reference.
