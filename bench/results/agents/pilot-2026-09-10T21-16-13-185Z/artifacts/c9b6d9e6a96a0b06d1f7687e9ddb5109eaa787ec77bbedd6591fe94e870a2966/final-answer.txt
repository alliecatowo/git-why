## What I found in the history

Using `git why`, the relevant history for this exact path is just three commits:

- **`48ee78f`** "Cache resolved sessions in-process to cut /api/session latency" — added a module-level `const cache = new Map()` keyed by `sessionId` alone.
- **`1a6c01e`** "Revert in-process session cache" — reverted it. The message is the crucial part:
  > The cache key was the session id, but session ids are only unique **per tenant**. On shared workers this served one tenant a different tenant's session, which is a **cross-tenant data leak** … Any future cache on this path must key on `(tenantId, sessionId)` and must not be process-global while workers are shared across tenants.
- **`9194016`** (HEAD) replaced the body with the "Uncached by design" note — the current, deliberately slow state.

So the naive speedup (a global map keyed by `sessionId`) is a trap that reintroduces a real security bug. The actual fix is caching again, but safely.

## What I changed and why

`resolveSession(io, sessionId)` still takes only `io` and `sessionId`, so the tenant identity has to come from the tenant-scoped IO adapter. I implemented:

1. **Scoped, not process-global** — the cache lives in a module-level `WeakMap` keyed by the `io` adapter, so entries are tied to that adapter's lifetime instead of being one map shared across every tenant a worker serves. This directly addresses "must not be process-global while workers are shared across tenants."
2. **Partitioned by tenant** — inside an adapter, entries are stored in a per-tenant bucket (`tenantId` → `sessionId` → result). I read the tenant from `io.tenantId` / `io.tenant_id` / `io.tenant`. This satisfies "must key on `(tenantId, sessionId)`" so identical session ids from different tenants can never collide.
3. **In-flight promise caching** — I cache the `loadSession` promise rather than only the resolved value, so a burst of concurrent requests for the same `(tenant, session)` collapses into a single backend load (important for the "under load" case).
4. **Failure handling** — rejected loads are evicted so a transient error isn't permanently cached.
