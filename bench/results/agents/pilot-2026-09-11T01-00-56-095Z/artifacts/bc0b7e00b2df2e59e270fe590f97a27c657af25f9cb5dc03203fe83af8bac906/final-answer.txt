The `requests` library switched from exclusively using `chardet` to using `charset_normalizer` (for Python 3) while keeping `chardet` as an optional fallback.

The primary reason for this change was to address license ambiguity. `chardet` is licensed under the LGPL, which can cause compliance issues for downstream projects that bundle `requests` into a single binary. By switching to the MIT-licensed `charset_normalizer` for Python 3, `requests` removed this licensing hurdle for those users.

This change was established in commit **2ed84f55b22f19a1e1e8eea2e50963dce62052d3**.

The commit message states:
> "Although using the (non-vendored) chardet library is fine for requests itself, but using a LGPL dependency the story is a lot less clear for downstream projects, particularly ones that might like to bundle requests (and thus chardet) in to a single binary -- think something similar to what docker-compose is doing. By including an LGPL'd module it is no longer clear if the resulting artefact must also be LGPL'd.
> 
> By changing out this dependency for one under MIT we remove all license ambiguity."
