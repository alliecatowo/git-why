## Summary

I found the curl security bug fix related to credentials leaking when following redirects to different protocols or ports.

**Commit SHA:** `620ea2141` (full SHA: `620ea21410030a9977396b4661806bc187231b79`)

**What the fix changed:**

The fix adds explicit checks when processing redirects to clear authentication credentials (username and password) if the redirect goes to:
1. A different port number, OR
2. A different protocol

**From the commit message and diff:**

The commit is titled "transfer: redirects to other protocols or ports clear auth" and includes the note "... unless explicitly permitted."

The key change in `lib/transfer.c` adds logic in the `Curl_follow` function that:
- Checks if a redirect targets a different port than the original connection
- Checks if a redirect targets a different protocol than the original connection
- If either condition is true, clears the `data->state.aptr.user` and `data->state.aptr.passwd` fields, removing the authentication credentials before following the redirect

**Specific diff excerpt:**
```c
/* Clear auth if this redirects to a different port number or protocol,
   unless permitted */
if(!data->set.allow_auth_to_other_hosts && (type != FOLLOW_FAKE)) {
  // ... checks for port and protocol differences ...
  if(clear) {
    Curl_safefree(data->state.aptr.user);
    Curl_safefree(data->state.aptr.passwd);
  }
}
```

This fix prevents the CVE-2022-27774 vulnerability where curl could unintentionally leak authentication credentials when following a redirect to a different protocol or port.
