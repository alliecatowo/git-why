## Answer

Yes, the default handling of unknown keys in Zod objects **did change**. 

**The Change:** 
In commit **`18854492b4b6e1648499f2f920c615dab187ee1a`** (September 17, 2020), Zod v2 introduced a breaking change where **object schemas now strip unknown keys by default instead of allowing them**.

**Supporting Evidence from the Commit:**

The commit message states: **"strip unknown keys by default"**

The README diff shows the breaking change notification:
```
- Object schemas now strip unknown keys by default, instead of throwing an error
```

The diff also demonstrates the behavioral change in documentation:
- **Before (v1):** Objects allowed unknown keys by default
  ```ts
  person.parse({
    name: 'bob dylan',
    extraKey: 61,
  });
  // => { name: "bob dylan", extraKey: 61 }
  ```

- **After (v2):** Objects strip unknown keys by default
  ```ts
  person.parse({
    name: 'bob dylan',
    extraKey: 61,
  });
  // => { name: "bob dylan" }
  ```

To preserve unknown keys in v2+, you must explicitly call `.passthrough()` on the object schema. The commit also introduced the complementary `.strict()` method to throw errors on unknown keys.
