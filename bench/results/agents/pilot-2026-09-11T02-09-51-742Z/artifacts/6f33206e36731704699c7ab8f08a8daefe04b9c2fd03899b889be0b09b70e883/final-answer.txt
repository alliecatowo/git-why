## Answer

Yes, the default handling of unknown keys in Zod objects changed. 

**The Change:** In commit **1885449** (dated 2020-09-17), the default behavior for unknown keys was changed from `'allow'` to `'strip'` (renamed to `'passthrough'` at the same time, but the semantic is key).

**What Changed:**
- Before: Unknown keys were allowed by default (mode: `'allow'`)
- After: Unknown keys are stripped/removed by default (mode: `'strip'`)

**Supporting Evidence from the commit diff:**

In `src/types/object.ts`, the default parameter for the `UnknownKeys` type parameter changed from:
```typescript
UnknownKeys extends UnknownKeysParam = 'allow',
```
to:
```typescript
UnknownKeys extends UnknownKeysParam = 'passthrough',
```

Additionally, the `ZodObject.create()` static method changed from:
```typescript
unknownKeys: 'allow',
```
to:
```typescript
unknownKeys: 'strip',
```

**The Commit Message:** `"strip unknown keys by default"`

This explains why extra keys now "just disappear" — that's the intended behavior after this change. If you want the old behavior where extra keys are kept, you would need to call `.passthrough()` (formerly `.allowUnknown()`) on your schema.
