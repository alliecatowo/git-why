## Answer

The requests library switched its default text-encoding guesser from **chardet** (LGPL-licensed) to **charset_normalizer** (MIT-licensed) due to licensing concerns, while maintaining chardet as a fallback for backwards compatibility.

### Supporting Commit

**Commit SHA:** `2ed84f55b22f19a1e1e8eea2e50963dce62052d3`

**Date:** July 7, 2021

**Title:** "Switch LGPL'd chardet for MIT licensed charset_normalizer (#5797)"

### Key Quote from Commit Message

> "Although using the (non-vendored) chardet library is fine for requests itself, but using a LGPL dependency the story is a lot less clear for downstream projects, particularly ones that might like to bundle requests (and thus chardet) in to a single binary -- think something similar to what docker-compose is doing. By including an LGPL'd module it is no longer clear if the resulting artefact must also be LGPL'd. By changing out this dependency for one under MIT we remove all license ambiguity."

### Implementation Details

From the commit diff, the key change in `requests/compat.py`:

```python
# Before:
import chardet

# After:
try:
    import chardet
except ImportError:
    import charset_normalizer as chardet
```

This means charset_normalizer is now the primary dependency for Python 3, with chardet as a fallback if installed. The commit also added an optional extra `use_chardet_on_py3` to allow users to explicitly opt-in to using chardet if needed.
