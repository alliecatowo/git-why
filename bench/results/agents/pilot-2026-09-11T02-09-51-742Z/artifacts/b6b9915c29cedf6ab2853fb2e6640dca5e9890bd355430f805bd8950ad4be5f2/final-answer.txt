## Answer

The requests library switched its default text-encoding guesser from **chardet to charset_normalizer**.

**Supporting commit:** `2ed84f55b22f19a1e1e8eea2e50963dce62052d3`

**Commit message excerpt:**
> Switch LGPL'd chardet for MIT licensed charset_normalizer (#5797)
> 
> Although using the (non-vendored) chardet library is fine for requests itself, but using a LGPL dependency the story is a lot less clear for downstream projects, particularly ones that might like to bundle requests (and thus chardet) in to a single binary -- think something similar to what docker-compose is doing. By including an LGPL'd module it is no longer clear if the resulting artefact must also be LGPL'd.
>
> By changing out this dependency for one under MIT we remove all license ambiguity.

**Key diff excerpt from setup.py:**
```
-    'chardet>=3.0.2,<5',
+    'charset_normalizer~=2.0.0; python_version >= "3"',
+    'chardet>=3.0.2,<5; python_version < "3"',
```

**Key diff excerpt from requests/compat.py:**
```
-import chardet
+try:
+    import chardet
+except ImportError:
+    import charset_normalizer as chardet
```

The reason for the switch was to remove license ambiguity for projects bundling requests. The chardet library is LGPL-licensed, which creates uncertainty about licensing when bundled in binaries. The charset_normalizer library is MIT-licensed, which eliminates this ambiguity. The code still prefers chardet if it's installed (as a fallback for backwards compatibility), but charset_normalizer became the default dependency for Python 3.
