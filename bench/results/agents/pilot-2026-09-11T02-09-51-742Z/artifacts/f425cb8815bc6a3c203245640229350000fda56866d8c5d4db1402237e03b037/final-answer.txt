## Summary

I found the security fix for the curl vulnerability where following a redirect could leak credentials to a different protocol or port.

**Commit SHA:** `620ea2141` (full: `620ea21410030a9977396b4661806bc187231b79`)

**Commit Message:**
```
transfer: redirects to other protocols or ports clear auth

... unless explicitly permitted.

Bug: https://curl.se/docs/CVE-2022-27774.html
Reported-by: Harry Sintonen
Closes #8748
```

**What the fix changed:**

The fix modified `lib/transfer.c` in the `Curl_follow()` function to clear authentication credentials when a redirect occurs to:
1. A different port number, OR
2. A different protocol/scheme

The implementation added code that:
- Detects when a redirect target has a different port than the original connection
- Detects when a redirect target has a different protocol/scheme than the original connection
- Clears the stored authentication credentials (`data->state.aptr.user` and `data->state.aptr.passwd`) when either condition is true
- Allows overriding this behavior only if explicitly permitted via `data->set.allow_auth_to_other_hosts`

**Key quote from the diff:**
```c
/* Clear auth if this redirects to a different port number or protocol,
   unless permitted */
if(!data->set.allow_auth_to_other_hosts && (type != FOLLOW_FAKE)) {
  ...

    infof(data, "Clear auth, redirects to port from %u to %u",
          data->info.conn_remote_port, port);
    clear = TRUE;
  }
  else {
    ...
    if(p && (p->protocol != data->info.conn_protocol)) {
      infof(data, "Clear auth, redirects scheme from %s to %s",
            data->info.conn_scheme, scheme);
      clear = TRUE;
    }
    ...
  }
  if(clear) {
    Curl_safefree(data->state.aptr.user);
    Curl_safefree(data->state.aptr.passwd);
  }
```
