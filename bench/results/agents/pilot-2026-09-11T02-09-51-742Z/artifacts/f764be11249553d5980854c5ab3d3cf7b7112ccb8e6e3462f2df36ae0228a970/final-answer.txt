## Answer

**The curl security bug (CVE-2022-27776)** involved credentials being leaked to different protocols or ports when following redirects.

**Commit SHA:** `6e659993952aa5f90f48864be84a1bbb047fc258`

**What the fix changed:**

The fix introduced a new function `allow_auth_to_host()` that checks three conditions before sending authentication headers and cookies on redirect:
1. Whether it's NOT a redirect (`!data->state.this_is_a_follow`)
2. Whether `.allow_auth_to_other_hosts` is explicitly enabled
3. **Most importantly**, it verifies that the **same host, same port, AND same protocol** are being used

The key changes in the commit:
- Added tracking of `first_remote_port` and **added `first_remote_protocol`** (new field added to `struct UrlState`)
- The function now checks: `(data->state.first_remote_port == conn->remote_port) && (data->state.first_remote_protocol == conn->handler->protocol)`
- Previously, the code only checked the hostname, allowing credentials to leak when redirecting to the same host but on a different port or protocol
- The fix ensures authentication headers (Authorization, Cookie, etc.) are only sent if all three factors match: **same host, same port, AND same protocol**
