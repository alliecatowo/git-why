## Answer

**Why:** Requests dropped `chardet` as its default/required character-detection dependency and switched to `charset_normalizer` for **licensing reasons**. `chardet` is LGPL-licensed, which created legal ambiguity for downstream projects that bundle/vendor requests (e.g. into a single binary), since it is unclear whether the resulting artifact must also be LGPL. `charset_normalizer` is MIT-licensed, removing that ambiguity.

**Supporting commit:**

```
2ed84f55b22f19a1e1e8eea2e50963dce62052d3
Switch LGPL'd chardet for MIT licensed charset_normalizer (#5797)
Author: Ash Berlin-Taylor
Date:   Wed Jul 7 00:55:02 2021 +0100
```

I confirmed this commit is an ancestor of the pinned HEAD (`dae7ef63...`).

**Quote from the commit message:**

> Although using the (non-vendored) chardet library is fine for requests itself, but using a LGPL dependency the story is a lot less clear for downstream projects, particularly ones that might like to bundle requests (and thus chardet) in to a single binary -- think something similar to what docker-compose is doing. By including an LGPL'd module it is no longer clear if the resulting artefact must also be LGPL'd.
>
> By changing out this dependency for one under MIT we remove all license ambiguity.
>
> As an "escape hatch" I have made the code so that it will use chardet first if it is installed, but we no longer depend upon it directly, although there is a new extra added, `requests[lgpl]`.

**Supporting diff excerpts:**

`setup.py` — the required dependency swap:
```diff
-    'chardet>=3.0.2,<5',
+    'charset_normalizer~=2.0.0; python_version >= "3"',
+    'chardet>=3.0.2,<5; python_version < "3"',
```

`requests/compat.py` — chardet becomes an optional fallback:
```diff
-import chardet
+try:
+    import chardet
+except ImportError:
+    import charset_normalizer as chardet
```

`requests/models.py` — documented behavior updated:
```diff
-        """The apparent encoding, provided by the chardet library."""
+        """The apparent encoding, provided by the charset_normalizer or chardet libraries."""
```

So the guesser itself is still reached through the same `chardet.detect(...)` call site, but the bundled/default library resolving that name changed: `charset_normalizer` is now the dependency (MIT), with `chardet` kept only as an opt-in/fallback escape hatch. No files were modified.
