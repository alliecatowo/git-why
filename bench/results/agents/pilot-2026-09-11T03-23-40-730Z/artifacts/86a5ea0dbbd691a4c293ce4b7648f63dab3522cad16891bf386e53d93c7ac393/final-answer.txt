## Answer

Yes — the default handling of unknown keys **did** change. Objects used to keep undefined/extra keys in the parsed output; now they are stripped. The change is established by this commit:

### `18854492b4b6e1648499f2f920c615dab187ee1a` — "strip unknown keys by default" (Colin McDonnell, 2020-09-17, during Zod 2 development)

The commit message itself is the answer: **"strip unknown keys by default"**.

The diff flips the object default from keeping unknown keys (`'allow'`, later renamed `'passthrough'`) to dropping them (`'strip'`):

**`src/types/object.ts`** — in `ZodObject.create` and `lazycreate`:
```diff
       t: z.ZodTypes.object,
       shape: () => shape,
-      unknownKeys: 'allow',
+      unknownKeys: 'strip',
       catchall: ZodNever.create(),
```
and the class-level generic default:
```diff
 export class ZodObject<
   T extends z.ZodRawShape,
-  UnknownKeys extends UnknownKeysParam = 'allow',
+  UnknownKeys extends UnknownKeysParam = 'passthrough',
```

**`README.md`** — documents both the new default and the history:
```diff
-- Object schemas now _allow_ unknown keys by default, instead of throwing an error
+- Object schemas now strip unknown keys by default, instead of throwing an error
```
```diff
-Zod object schemas allow unknown keys.
+By default Zod object schema strip unknown keys from the output.
 
-> ⚠️ Before Zod 2 object schema did NOT allow unknown keys by default.
+> ⚠️ Before version 2, Zod did NOT allow unknown keys by default.
```
with the example changing from `// => { name: "bob dylan", extraKey: 61 }` to `// => { name: "bob dylan" }`.

**`src/parser.ts`** — the runtime copy of extra keys becomes opt-in:
```diff
-        if (def.unknownKeys === 'allow') {
+        if (def.unknownKeys === 'passthrough') {
           for (const key of extraKeys) {
             objectPromises[key] = PseudoPromise.resolve(data[key]);
           }
```

### Timeline of the default

1. **Zod 1:** object schemas *threw* on unknown keys (per the README note quoted above).
2. **Early Zod 2 development** (up to the parent of `18854492`): default was `'allow'` — extra keys were **kept** in the output. This matches what the question remembers.
3. **Since `18854492`** (all of Zod 3 and the current v4 checkout): default is `'strip'` — extra keys disappear from the parsed output. To keep them you must call `.passthrough()` (or, for backward compat at the time, `.nonstrict()`).

The current v4 checkout confirms the behavior is still strip: `packages/zod/src/v4/classic/schemas.ts` declares `export function object(...): ZodObject<util.Writeable<T>, core.$strip>`, and the core object parser builds a fresh result object writing only the shape's keys. The v4-era commits mentioning strip (`b142ea8f` "Fix $strip", `222a6637` "Change ZodObject default to $strip. Set inst.shape in zod mini", June 2025) only corrected TypeScript-level default type parameters and return types — they did not change the runtime default, which was already strip.
