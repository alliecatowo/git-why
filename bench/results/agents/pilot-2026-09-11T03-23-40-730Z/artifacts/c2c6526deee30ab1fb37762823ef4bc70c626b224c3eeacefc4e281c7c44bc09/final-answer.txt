## Answer

The switch was made for **licensing reasons**: chardet is LGPL-licensed, while its replacement `charset_normalizer` is MIT-licensed. Requests wanted to eliminate the license ambiguity that an LGPL dependency created for downstream projects that bundle requests into a single binary.

**Establishing commit:** `2ed84f55b22f19a1e1e8eea2e50963dce62052d3`

Commit message (written by Ash Berlin-Taylor, PR #5797):

> **Switch LGPL'd chardet for MIT licensed charset_normalizer (#5797)**
>
> Although using the (non-vendored) chardet library is fine for requests itself, but using a LGPL dependency the story is a lot less clear for downstream projects, particularly ones that might like to bundle requests (and thus chardet) in to a single binary -- think something similar to what docker-compose is doing. By including an LGPL'd module it is no longer clear if the resulting artefact must also be LGPL'd.
>
> By changing out this dependency for one under MIT we remove all license ambiguity.
>
> As an "escape hatch" I have made the code so that it will use chardet first if it is installed, but we no longer depend upon it directly, although there is a new extra added, `requests[lgpl]`. ... (In my non-exhaustive tests it detects the same encoding as chartdet in every case I threw at it)

Supporting diff from that commit (`setup.py`):

```diff
-    'chardet>=3.0.2,<5',
+    'charset_normalizer~=2.0.0; python_version >= "3"',
+    'chardet>=3.0.2,<5; python_version < "3"',
```

and from `HISTORY.md`:

> Instead of `chardet`, use the MIT-licensed `charset_normalizer` for Python3 to remove license ambiguity for projects bundling requests. If `chardet` is already installed on your machine it will be used instead of `charset_normalizer` to keep backwards compatibility.

I confirmed this commit is an ancestor of the checked-out `HEAD` (`dae7ef63...`), and the current tree reflects it: `pyproject.toml` lists `charset_normalizer>=2,<4` as the dependency, with `use_chardet_on_py3 = ["chardet>=3.0.2,<8"]` retained as the opt-in escape hatch, and `src/requests/compat.py` resolving chardet first but falling back to `charset_normalizer`. (No files were modified.)
