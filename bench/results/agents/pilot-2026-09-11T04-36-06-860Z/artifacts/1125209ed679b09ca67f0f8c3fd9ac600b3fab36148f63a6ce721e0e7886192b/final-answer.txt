## Answer

Yes — this was a real, deliberate behavior change, not a misremembering. Zod object schemas used to **pass through** (keep) unknown/extra keys by default; the default was changed to **strip** them.

**Commit:** `18854492b4b6e1648499f2f920c615dab187ee1a` — "strip unknown keys by default" (Colin McDonnell, 2020‑09‑17)

Supporting diff (in `src/types/object.ts`, the `ZodObject.create`/`lazycreate` factories):

```diff
     return new ZodObject({
       t: z.ZodTypes.object,
       shape: () => shape,
-      unknownKeys: 'allow',
+      unknownKeys: 'strip',
       catchall: ZodNever.create(),
```

and the accompanying new test added in the same commit (`src/__tests__/object.test.ts`):

```ts
test('strip by default', () => {
  const val = z.object({ points: z.number() }).parse(data);
  expect(val).toEqual({ points: 2314 });
});
```

The same commit also renamed the opt-in methods to match today's API: `.allowUnknown()` → `.passthrough()` (for keeping extra keys) and `.stripUnknown()` → `.strip()`, and changed the internal `UnknownKeysParam` union from `'allow' | 'strict' | 'strip'` to `'passthrough' | 'strict' | 'strip'`. The `README.md` change in the same commit spells out the user-facing effect: *"By default Zod object schema strip unknown keys from the output."* with the note *"⚠️ Before version 2, Zod did NOT allow unknown keys by default."* (that note is slightly imprecise about the exact prior default, but the code diff above is unambiguous: before this commit the default was `'allow'`, i.e. passthrough).

So: you're not misremembering — before this commit (part of the Zod v2 line of work, per the neighboring "Added v2 announcement message" commit `7d0532e`), unknown keys were kept in the parsed output by default; after it, they're stripped by default unless you call `.passthrough()`. This default has held ever since (verified still true in the current `packages/zod/src/v3/types.ts` legacy-compat code at HEAD, where `unknownKeys: "strip"` remains the default).
