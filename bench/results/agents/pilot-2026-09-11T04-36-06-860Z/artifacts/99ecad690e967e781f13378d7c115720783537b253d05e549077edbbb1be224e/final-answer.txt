## Answer

Yes — **requests** originally used **`chardet`** as its default encoding-detection library. It switched to **`charset_normalizer`** because `chardet` is LGPL-licensed, which created license-compatibility problems for downstream projects that wanted to bundle/vendor `requests` (and therefore `chardet`) into a single binary — the LGPL could "infect" the resulting artifact's licensing. `charset_normalizer` is MIT-licensed, removing that ambiguity. To minimize breakage, the maintainers made the new code prefer `chardet` if it's already installed (falling back to it first), otherwise it falls back to `charset_normalizer`, and added a `requests[chardet]`/`use_chardet_on_py3`-style extra as an "escape hatch" for people who still want `chardet`'s behavior.
