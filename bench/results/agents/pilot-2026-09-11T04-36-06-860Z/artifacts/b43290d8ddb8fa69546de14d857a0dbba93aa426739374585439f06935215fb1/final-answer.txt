## Answer

**Yes, it was renamed.** The `LPOS` command originally used the option keyword `FIRST` to specify which matching occurrence to return, and it was later renamed to `RANK`.

### Supporting commit

**SHA: `a5a3a7bbc61203398ecc1d5b52c76214f5672776`**

```
Author: antirez <antirez@gmail.com>
Date:   Wed Jun 24 09:07:17 2020 +0200

    LPOS: option FIRST renamed RANK.
```

The diff shows the rename directly in `src/t_list.c`, including the doc comment change:

```diff
-/* LPOS key element [FIRST rank] [COUNT num-matches] [MAXLEN len]
+/* LPOS key element [RANK rank] [COUNT num-matches] [MAXLEN len]
  *
- * FIRST "rank" is the position of the match, so if it is 1, the first match
+ * The "rank" is the position of the match, so if it is 1, the first match
```

and in the option-parsing code:

```diff
-        if (!strcasecmp(opt,"FIRST") && moreargs) {
+        if (!strcasecmp(opt,"RANK") && moreargs) {
             j++;
             if (getLongFromObjectOrReply(c, c->argv[j], &rank, NULL) != C_OK)
                 return;
             if (rank == 0) {
-                addReplyError(c,"FIRST can't be zero: use 1 to start from "
+                addReplyError(c,"RANK can't be zero: use 1 to start from "

```

The commit also updates every `FIRST`-using test in `tests/unit/type/list.tcl` to use `RANK` instead (e.g. `LPOS mylist c FIRST 1` → `LPOS mylist c RANK 1`).

### Context (for completeness)

For reference, the `FIRST` keyword itself had been introduced shortly before, in commit `e63a5ba12223a7ab7d817ab42983be683aec0aca` ("LPOS: implement the final design.", 2020-06-10), during the initial development of `LPOS` (which itself evolved from an earlier command called `LRANK`, introduced in `a7936ef96...` "LRANK: Add command (the command will be renamed LPOS)."). Only two weeks later, `a5a3a7bbc` renamed `FIRST` to `RANK`, which is the name that has stuck in all subsequent Redis releases — explaining why old examples/memories reference `FIRST` while current documentation says `RANK`.
