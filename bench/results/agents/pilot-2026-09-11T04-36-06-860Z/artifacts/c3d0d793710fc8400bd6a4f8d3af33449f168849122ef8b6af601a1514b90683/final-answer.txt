**The bug:** This is CVE-2022-27774. When curl followed an HTTP redirect that pointed to a *different port* or a *different protocol* than the original request, it would keep sending the same authentication credentials (and, in a related sibling fix, SRP/TLS credentials) to that new destination — leaking the user's credentials to a host/service they were never intended for.

**The fix:** curl now clears the stored auth credentials (username/password) whenever a redirect changes either the destination port or the protocol/scheme, unless the application has explicitly opted in to allow credentials to be sent to other hosts/ports (`CURLOPT_REDIR_PROTOCOLS`/allow-auth-to-other-hosts style opt-in).

This precisely changes redirect-following behavior so that basic/plain-text username/password credentials (`data->state.aptr.user` / `data->state.aptr.passwd`) are wiped before the request is repeated against the new port or protocol, closing the credential-leak path. (Two related follow-up commits, `139a54ed0` "openssl: don't leak the SRP credentials in redirects either" and `093531556` "gnutls: don't leak the SRP credentials in redirects", extend the same protection to TLS-SRP credentials for the respective backends.)
