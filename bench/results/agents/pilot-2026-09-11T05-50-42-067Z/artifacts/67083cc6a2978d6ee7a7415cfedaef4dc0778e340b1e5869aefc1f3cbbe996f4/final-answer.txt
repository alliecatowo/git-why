Yes, the default handling of unknown keys in Zod object schemas did change. 

### What Changed?
* **In Zod v1:** Unknown keys were rejected by default (parsing threw an error unless `.nonstrict()` was called).
* **Early Zod v2 pre-releases:** Zod briefly changed to **allow/passthrough** unknown keys by default (meaning extra properties were kept/passed through).
* **Zod v2 final/onwards:** The default behavior was changed to **strip** unknown keys from the output.
