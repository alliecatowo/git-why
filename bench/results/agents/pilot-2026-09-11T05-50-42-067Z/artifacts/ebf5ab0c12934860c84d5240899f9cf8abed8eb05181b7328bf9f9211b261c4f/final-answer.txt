There was a curl security bug (associated with **CVE-2022-27774**) where following a redirect could leak credentials to a different protocol or port. 

---

### What the Fix Changed

The fix introduces check logic in `Curl_follow()` (where curl handles redirects and Location-following) to automatically clear the HTTP username and password credentials if the redirect destination uses a different port number or protocol scheme, unless sending authorization credentials to other hosts is explicitly allowed via configuration.

Specifically, it:
1. Compares the redirect destination port against the original port (`data->info.conn_remote_port`). If they differ, it sets a clear flag to `TRUE`.
2. Compares the redirect destination protocol scheme against the original protocol (`data->info.conn_protocol`). If they differ, it sets a clear flag to `TRUE`.
3. If the clear flag is `TRUE` (and the transfer is not a fake follow and credentials transfer is not explicitly configured to allow auth to other hosts), it frees and clears the username and password buffers:
   ```c
   Curl_safefree(data->state.aptr.user);
   Curl_safefree(data->state.aptr.passwd);
   ```

A follow-up fix was also merged to prevent SRP (Secure Remote Password) credentials from being leaked over OpenSSL TLS redirects by using `Curl_allow_auth_to_host()`.
