## Final Answer

I have completed the engineering brief for the burntsushi-ripgrep repository. Here are the findings for all 6 questions:

### 1. **Manual Page Dash Bug**
**Commit:** 74959a1
The issue was that roff renderers would convert regular hyphens in flag names into special Unicode hyphens, making man page searches fail. The fix escaped all hyphens in flag names.
Quote: *"Apparently, if we don't do this, some roff renderers with use a special Unicode hyphen. That in turn makes searching a man page not work as one would expect."*

### 2. **Dependency Bump for Router Firmware**
**Commit:** 53279db
Switched from `jemallocator` to `tikv-jemallocator` because the latter contained a critical fix for compilation on riscv64gc-unknown-linux-musl, enabling ripgrep to build on OpenWrt.
Quote: *"It is now a recommended crate for jemalloc and it contains an [important fix for compilation on riscv64gc-unknown-linux-musl], I bumped into this when I was trying to [build ripgrep on OpenWrt]."*

### 3. **Thing That Kept Breaking**
**Commit:** 9d62eb9
The CRLF hack (a workaround that transformed `$` into `(?:\r?$)`) was finally removed once Rust's regex engine added native CRLF support. It never worked correctly in all cases.
Quote: *"Now that Rust's regex crate finally supports a CRLF mode, we can remove this giant hack in ripgrep to enable it. (And assuredly did not work in all cases.)"*

### 4. **Windows Eager Executable Resolution**
**Commit:** 9164158
The decompression reader builder was being initialized eagerly on Windows, triggering resolution of all possible decompression binaries even when not needed. Now it's only built when `-z/--search-zip` is actually used.
Quote: *"In particular, on Windows, the various binaries are eagerly resolved... It would probably be better to change the decompression reader to do lazy resolution only when the binary is needed."*

### 5. **Glob Trailing Dots Bug**
**Commit:** 4df1298
Globs ending with dots (like `asdf.`) were incorrectly treated as having no filename. The file_name function was incorrectly returning None for paths ending with any dot instead of only for paths ending in `..`.
Quote: *"Fix a bug where ripgrep would mishandle globs that ended with a `.`."*

### 6. **Max Count with Context Bug**
**Commit:** 0ca96e0
Using `-m` (max count) with `-A` (after context) would print more matches than the limit. The after-context state was being reset on each match rather than decremented when the match limit was exceeded.
Quote: *"Fixes a bug where using `-m` and `-A` printed more matches than the limit."*
