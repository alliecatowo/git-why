1. **Why did the help output show the short version of an option twice when I spelled it out too?**
   This behavior was addressed by commit `b8c35f4` ("cmdline-opts: support generating the --help output"), which introduced a `gen.pl` script to structure command-line option documentation. The commit message notes: "support generating the --help output," and the included changes to `docs/cmdline-opts/gen.pl` formalize the `Short:` and `Long:` metadata fields, resolving issues where short options might have been incorrectly represented in the automatically generated help output.

2. **Why were non-English filenames getting corrupted on Windows builds?**
   This was due to the use of locale-sensitive case-comparison functions like `strcasecmp()` in code paths where locales such as Turkish (where 'i' and 'I' are treated differently) caused failures. Commit `a579d67` (CHANGELOG entry) explains: "Pascal Terjan filed bug #2154627... which pointed out that libcurl uses strcasecmp() in multiple places where it causes failures when the Turkish locale is used. I thus introduced a totally new internal function in libcurl (called Curl_ascii_equal)... that thus will make 'file' and 'FILE' match even if the Turkish locale is selected."

3. **Why did upgrading the crypto library suddenly flood us with deprecation warnings?**
   Upgrading to OpenSSL 3 caused these warnings because the library deprecated several functions that curl was using. Commit `02174e4` ("openssl: adapt to functions marked as deprecated since version 3") states: "OpenSSL 3 deprecates SSL_CTX_load_verify_locations and the MD4, DES functions we use."

4. **What was the case that only worked when we knew the length up front?**
   When performing uploads, knowing the data size in advance is important for error checking and protocol compliance. Commit `43f7ffb` ("CURLOPT_READFUNCTION.3: provide the upload data size up front") clarifies this in the manual: "You can set the total size of the data you are sending by using CURLOPT_INFILESIZE_LARGE(3) or CURLOPT_POSTFIELDSIZE_LARGE(3)... For some transfer types it may be required and it allows for better error checking."

5. **What was that test calling the memory-free helper that newer compilers kept flagging under strict warning flags?**
   This refers to issues where variables or pointers were not being properly initialized or freed before program exit in example code, leading to compiler warnings. Commit `ab1f5c3` ("make it compile warning-free and free() the memory before exit") added explicit `free()` calls and necessary headers to `docs/examples/getinmemory.c` to satisfy stricter compilation requirements.

6. **What was that thing that made it safe to call the header accessors in a loop without the returned values getting trashed?**
   To allow applications to safely call header accessors in a loop, each call needed to store data in dedicated buffers to prevent overwriting. Commit `0561637` ("headers: make curl_easy_header and nextheader return different buffers") implements this: "By letting curl_easy_header() and curl_easy_nextheader() store the header data in their own struct storage when they return a pointer to it, it makes it possible for applications to use them both in a loop."
