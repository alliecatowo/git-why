Based on the examination of the git history for the `redis-redis` repository, here are the answers to the questions regarding the identified issues:

1.  **Access rule overlap issue:** When adding a new ACL rule, the system attempted to strip out overlapping existing rules, but a bug caused the search to resume incorrectly, potentially skipping subsequent rules or leaving the ACLs in an inconsistent state. This was fixed in commit **7c179f9bf**. The commit message states: "When adding a new ACL rule was added, an attempt was made to remove any 'overlapping' rules. However, there when a match was found, the search was not resumed at the right location..."
2.  **Background maintenance job growth/shrinking:** The background maintenance jobs (specifically within the context of memory management and `jemalloc`) were updated to handle symmetrical growth and shrinking of allocations to optimize memory usage and prevent fragmentation. This logic is part of the `jemalloc` integration and memory management refactoring found in commits like **6d23d3ac3**, which updated `jemalloc` and implemented "in-place huge allocation growing and shrinking."
3.  **File handle zero bug:** A bug occurred where zero-length lists could be saved/loaded incorrectly, often leading to crashes or invalid states when a file handle or list node was represented as zero or NULL inappropriately. This was addressed in commit **a1944c3e4**. The commit message notes: "Fix saving of zero-length lists... materialized as quicklists with the first node set to NULL, were iterated in the wrong way while they are saved, leading to a crash."
4.  **Database growth bug during snapshot loading:** A bug in the database loading process (`rdbLoad`) caused it to fail to expand the dictionary for new databases, resulting in a database that stopped growing after the initial expansion. This was addressed in commit **b730404c2**, titled "Fix multi dbs donot dbExpand when loading RDB."
5.  **Bit-position lookup list vs. string:** When the `BITPOS` command was called against a key holding a list instead of a string, it originally either crashed or returned inconsistent results; it was updated to correctly return a `WRONGTYPE` error. This was clarified through several commits, including **a1c9c05e1** and **45d331069**, which ensure proper type checking for bitwise commands against non-string types.
6.  **Flaky expiration test:** A flaky test occurred in the expiration suite because a volatile key was leaked from one test into the next, causing an unexpected `DEL` command to be injected into the replication stream, leading to failures in subsequent tests. This was fixed in commit **fb140a1bf**. The commit message states: "The root cause is that one test (`5 keys in, 5 keys out`) is leaking a volatile key that can expire while another later test... is running."
